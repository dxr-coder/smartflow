# 星辰科技信息安全管理制度

版本：1.0
生效日期：2026-03-01
适用范围：全体员工、实习生、外包人员及第三方接入人员
归口部门：信息技术部（IT 安全组）

---

## 一、总则

### 1.1 目的
为规范星辰科技（以下简称"公司"）信息安全管理，保护公司数据资产、业务系统和员工个人信息的机密性、完整性与可用性，防范网络攻击、数据泄露与违规使用风险，依据《中华人民共和国网络安全法》《数据安全法》《个人信息保护法》及网络安全等级保护 2.0 要求，结合公司实际，制定本制度。

### 1.2 适用对象
- 全体正式员工、试用期员工、实习生
- 使用公司设备或接入公司网络的外包、驻场人员
- 接触公司数据的第三方合作伙伴、供应商
- 访问公司系统的云服务商、SaaS 服务商

### 1.3 管理原则
- **最小权限原则**：任何人只获得完成工作所必需的最小数据与系统权限
- **职责分离原则**：关键操作的申请、执行、审计由不同人员承担
- **纵深防御原则**：边界、网络、主机、应用、数据多层设防，不依赖单一控制点
- **谁主管谁负责**：部门负责人是本部门数据安全第一责任人，IT 安全组负责技术管控与监督

### 1.4 组织与职责
- IT 安全组：分机 8110（7×24 小时），负责安全策略制定、技术防护、事件处置、合规审计
- IT 服务台：分机 8100（工作日 9:00-18:00，3 楼现场），负责终端安全软件安装、加密配置、一般报障转安全组
- 各部门负责人：审批本部门权限申请、数据外发申请，配合安全事件调查
- 全体员工：遵守本制度，完成年度安全培训，发现隐患及时上报
- CTO：特权账号开通、重大安全事项的最终审批人

## 二、数据分级与分类

### 2.1 分级标准

| 级别 | 定义 | 典型数据 | 泄露影响 |
|------|------|---------|---------|
| 公开级 | 可对外发布 | 产品介绍、招聘 JD、官网新闻 | 无 |
| 内部级 | 仅限公司内部知悉 | 制度文档、会议纪要、普通项目资料 | 造成内部管理困扰 |
| 机密级 | 限定知悉范围 | 财务数据、客户名单、代码仓库、源代码 | 严重损害公司利益 |
| 绝密级 | 仅限核心管理层 | 并购计划、融资信息、未公开财报、核心算法 | 危及公司生存 |

### 2.2 定级与标识
- 新产生的数据由创建人初步定级，部门负责人确认
- 数据归属不明确的，默认按"内部级"管理
- 机密级及以上文件必须在文档页眉或文件名中标注级别，例如"【机密】Q3 客户名单"
- 电子文件可通过企业网盘的权限分级功能设置访问范围

### 2.3 数据生命周期要求
- **收集**：遵循最小必要原则，不得超范围收集客户与员工个人信息
- **存储**：机密级及以上数据必须存储在公司系统（企业网盘、代码仓库、OA），禁止存放于个人网盘、个人邮箱、私人电脑
- **使用**：机密级数据的查询、导出需留痕；绝密级数据访问需事先审批
- **共享**：对外共享前需数据 Owner 审批；客户数据对外提供需脱敏处理
- **销毁**：纸质机密文件使用碎纸机销毁；报废介质必须消磁或物理破坏，由 IT 统一处理，禁止直接丢弃

### 2.4 数据外发管理
- 内部级及以下数据：正常业务沟通可直接发送
- 机密级数据：发送外部需在 OA 提交"数据外发申请"，部门负责人审批；邮件必须加密发送并设置有效期
- 绝密级数据：原则上不外发；确需提供的须 CTO 审批，并签署保密协议
- 数据误发的处置：立即联系 IT 安全组（分机 8110）尝试召回，同时通知收件人删除，参照第十章应急流程处理

## 三、访问控制

### 3.1 账号管理
- 企业邮箱统一格式 firstname.lastname@starcorp.com，入职自动开通，OA、内网系统与之同名
- 禁止多人共用账号；因共用账号导致的安全事件由账号所属人承担全部责任
- 共享类邮箱（如 it-helpdesk@starcorp.com、security@starcorp.com）指定专人管理，访问成员名单报 IT 备案
- 离职账号在离职当日全部停用，转岗原权限 3 个工作日内回收（与《IT 服务指南》一致）

### 3.2 密码策略
- 密码长度不少于 12 位，包含大小写字母、数字、特殊符号中至少 3 类
- 密码有效期 90 天，到期强制更换；不得与最近 5 次使用过的密码重复
- 连续 5 次密码错误，账号锁定 30 分钟
- 以上基线适用于邮箱、OA、VPN 及所有接入公司账号体系的业务系统，任何系统不得低于该标准

### 3.3 权限管理
- 权限申请：在 OA 提交权限申请单，说明系统、权限范围、用途，直属主管 + 系统 Owner 审批
- 特权账号（数据库、服务器、网络设备）：需 CTO 审批，使用必须通过堡垒机并开启操作录屏
- 权限复核：每季度 IT 安全组组织一次权限复核，清理僵尸账号、越权权限，各部门配合在 5 个工作日内完成确认
- 临时权限：外包、驻场人员权限按项目期限开通，项目结束当日回收，最长不超过 90 天

### 3.4 远程访问
- 远程办公必须通过 VPN 接入，使用企业邮箱账号 + 动态令牌（30 秒刷新）
- VPN 账号仅限本人使用，禁止转发令牌、共享账号
- 高危操作（数据库变更、生产发布）禁止在公共网络环境下执行

## 四、数据加密

### 4.1 传输加密
- 所有对外 Web 服务必须启用 HTTPS（TLS 1.2 及以上），禁止明文 HTTP 传输业务数据
- 邮件系统启用强制 TLS 传输加密
- 系统间接口调用采用 HTTPS 或签名机制，禁止内网明文裸奔接口暴露至公网
- 远程运维通道仅允许 SSH、RDP over VPN，禁止直接暴露远程桌面端口至互联网

### 4.2 存储加密
- 公司配发笔记本电脑必须开启全盘加密（Windows：BitLocker，macOS：FileVault），由 IT 在设备发放前统一配置
- 数据库中的密码、身份证号、银行卡号等敏感字段必须加密存储（不可逆哈希或对称加密）
- 备份介质、异地容灾数据在传输与存放过程中均须加密，密钥与数据分离保管

### 4.3 移动介质
- 禁止使用个人 U 盘拷贝公司数据；文件传输一律使用企业网盘
- 因工作需要使用移动硬盘的，须使用 IT 发放的加密设备并登记编号
- 外部介质插入公司电脑前须经防病毒扫描，自动运行功能一律禁用

## 五、日志与审计

### 5.1 日志范围
以下系统必须开启操作日志并同步至日志审计平台：
- 企业邮箱（登录、外发、转发、附件下载）
- OA 系统（登录、审批、导出）
- VPN（登录时间、来源 IP、流量）
- 堡垒机与服务器（所有命令级操作）
- 代码仓库（克隆、推送、权限变更）
- 门禁与访客系统（与行政访客管理制度衔接）

### 5.2 日志留存期限

| 日志类型 | 留存期限 | 存储位置 |
|---------|---------|---------|
| 安全设备日志（防火墙、EDR） | 180 天 | 日志审计平台 |
| 业务系统审计日志 | 1 年 | 日志审计平台 |
| 特权操作录屏 | 2 年 | 归档存储 |
| 门禁与访客记录 | 90 天 | 行政门禁系统 |
| 邮件审计日志 | 180 天 | 邮件网关 |

### 5.3 审计执行
- IT 安全组每月进行日志抽查，覆盖登录异常、批量导出、越权访问三类场景
- 每季度开展一次全面审计，输出审计报告报 CTO
- 特权账号操作记录 100% 复核，发现违规操作 24 小时内启动调查
- 审计发现的问题形成整改清单，责任部门限期整改，逾期纳入部门考核

## 六、终端安全基线

### 6.1 必备安全组件
公司配发终端（笔记本、台式机）必须安装并保持运行：
- EDR 终端安全软件（防病毒 + 勒索诱捕），禁止卸载、退出
- 全盘加密（BitLocker / FileVault）
- 防火墙（系统自带或企业版）
- 统一补丁管理客户端

### 6.2 基线配置
- 开机密码 + 屏保密码，5 分钟无操作自动锁屏；离开工位超过 10 分钟必须手动锁屏（Windows：Win+L，Mac：Ctrl+Command+Q）
- 关闭自动运行、禁用 USB 大容量存储写入（IT 发放的加密设备除外）
- 关闭远程桌面默认开启，确需使用经审批后开放
- 浏览器启用反钓鱼防护，拦截恶意网站

### 6.3 补丁管理
- 操作系统与常用软件补丁由 IT 统一推送，每月一次例行更新窗口
- 高危漏洞补丁：7 天内完成全网终端修复
- 无法自动更新的特殊终端，由 IT 安全组手工评估并安排修复

### 6.4 禁止行为
- 安装破解版、来路不明的软件
- 运行挖矿程序、翻墙工具（公司批准的国际研发用途除外）
- 关闭、篡改安全软件
- 私自搭建对外服务、私接无线路由器
- 将公司设备交给非公司人员使用或带出境外（境外出差需 IT 备案并清空数据）

## 七、网络与边界安全

### 7.1 网络分区
- 办公网、服务器区、访客网相互隔离，访客网络无法访问任何内部系统
- 研发网与办公网逻辑隔离，代码服务器仅研发网可直连
- 具体 VLAN 划分与 IP 规划见《网络与系统运维规范》

### 7.2 无线安全
- 办公 WiFi（SSID：StarCorp）采用企业邮箱账号认证，同账号最多 3 台设备在线
- 访客 WiFi（SSID：StarCorp-Guest）采用手机验证码认证，限速 10Mbps，与办公网完全隔离
- 禁止私设热点转发公司网络，禁止将企业 WiFi 密码外传（企业认证模式下亦不允许代登录）

### 7.3 边界防护
- 出口防火墙默认拒绝策略，按需放行；高危端口（3389、445、23 等）对互联网默认封禁
- Web 应用防火墙保护对外业务系统，每月更新防护规则
- DNS 过滤恶意域名，阻断已知钓鱼与木马站点
- 每年至少开展一次渗透测试，高危漏洞修复不超过 15 天

## 八、第三方接入安全

### 8.1 准入评估
第三方（供应商、外包、SaaS 服务商）接入公司网络或处理公司数据前，须完成：
- 资质审查：营业执照、相关安全认证（如 ISO 27001 优先）
- 签署《保密协议》与《数据安全责任书》，明确数据用途、期限、违约责任
- 填写安全问卷，由 IT 安全组评估，高风险项须整改后方可接入
- 审批链：对接部门负责人 + IT 安全组，涉及数据出境或绝密数据的加签 CTO

### 8.2 接入管控
- 第三方远程接入使用专用 VPN 账号，绑定固定时段（如仅工作日 9:00-18:00）、固定 IP
- 所有操作经堡垒机代理并全程录屏，账号到期自动停用
- 驻场外包人员使用独立 VLAN 段 IP，禁止接入研发网核心资产
- 门禁权限按《来访接待与安全管理制度》办理，仅开放必要区域

### 8.3 数据交付
- 向第三方交付数据须脱敏，交付内容、范围在 OA 留痕
- 项目结束后 5 个工作日内，第三方须返还或销毁数据并出具书面证明
- SaaS 服务商处理公司数据的，须确认数据存储地、加密方式、删除机制，合同中明确数据归属公司

## 九、安全培训与演练

### 9.1 培训体系
- 新员工培训：入职首周包含信息安全模块（与 HR 新员工培训衔接），考核通过方可开通生产权限
- 年度全员培训：每年 3 月统一开展，覆盖最新威胁案例与制度更新，完成率纳入部门考核
- 专项培训：研发人员每年至少 1 次安全开发培训（SDL）；财务、HR 等敏感岗位每年 1 次数据保护专项培训
- 管理者培训：部门负责人每年 1 次安全管理责任培训

### 9.2 钓鱼演练
- IT 安全组每季度组织一次钓鱼邮件演练，模拟账号验证、快递通知、发票查收等场景
- 点击演练链接的员工收到即时安全提醒并记录一次
- 同一年度内累计 3 次点击的员工，必须参加安全复训
- 演练结果匿名化后在全公司通报，不与绩效直接挂钩，但作为部门安全考核输入

### 9.3 宣传与告警
- 重大安全事件（如行业高危漏洞爆发）通过企业微信 24 小时内发布全员防护提醒
- 每季度发布一期《安全月报》，通报钓鱼演练、漏洞修复、事件处理情况

## 十、安全事件应急响应

### 10.1 事件分级

| 级别 | 场景 | 响应要求 |
|------|------|---------|
| P1 重大 | 勒索加密、核心数据大规模泄露、生产系统被入侵 | 立即电话上报 IT 安全组 8110，15 分钟内响应 |
| P2 较大 | 单个账号被盗用、钓鱼得逞涉及内部数据、病毒扩散 | 30 分钟内上报，2 小时内遏制 |
| P3 一般 | 可疑邮件未造成损失、单机异常、误发内部级文件 | 当日内上报，按流程处置 |
| P4 轻微 | 咨询、误报、策略误拦截 | 服务台常规处理 |

### 10.2 上报渠道
- 电话：IT 安全组分机 8110（7×24 小时）
- 邮箱：security@starcorp.com
- 企业微信：IT 服务台 → 安全事件上报
- 发现电脑异常（频繁蓝屏、异常弹窗、文件被加密）：先断网再上报，防止扩散

### 10.3 响应流程
1. **发现与上报**：员工发现异常 30 分钟内上报，任何人不得私自处置或隐瞒
2. **研判定级**：IT 安全组 15 分钟内判定级别（对齐 IT 服务台紧急级 SLA：15 分钟响应、4 小时解决）
3. **遏制**：隔离受感染终端、禁用被盗账号、封堵攻击入口
4. **根除**：清除恶意程序、修复漏洞、重置凭证
5. **恢复**：在监控下恢复业务，核心系统恢复前通知相关部门
6. **复盘**：事件结束后 5 个工作日内输出复盘报告，P1/P2 事件报 CTO
7. **改进**：复盘结论转化为策略、培训或流程改进项，跟踪闭环

### 10.4 典型事件处置要点
- **勒索加密**：立即断网勿重启，保留现场，联系 IT 安全组；禁止私自支付赎金
- **账号疑似泄露**：立即修改密码（符合 12 位复杂度要求），联系 8110 强制下线所有会话
- **数据误发**：立即召回 + 通知删除 + 8110 登记事件；机密级以上同时通知部门负责人
- **钓鱼中招**：修改相关密码，全盘扫描，短期内留意异常登录提醒

### 10.5 事件定级与通报
- P1 事件在遏制后 2 小时内向管理层通报初步结论
- 涉及个人信息泄露的，按法律规定评估是否需要对外告知及监管报备，由 CTO 与法务共同决定
- 全年安全事件统计纳入年度安全报告

## 十一、等保合规与安全检查

### 11.1 等级保护
- 公司核心业务系统按网络安全等级保护第三级标准建设与备案
- 每年委托具备资质的测评机构开展等级测评，测评发现的问题按期整改
- 系统上线、架构重大变更后，同步评估是否影响定级与备案状态

### 11.2 自查与检查
- IT 安全组每半年组织一次全网安全自查，覆盖终端合规率、账号权限、日志完整性、漏洞修复率
- 自查结果与整改计划报 CTO，重大缺陷 30 天内整改完毕
- 配合监管部门及客户的合规审计，按需提供制度、日志、测评报告等材料

### 11.3 资产与漏洞管理
- 建立 IT 资产台账（服务器、网络设备、终端、软件），与《办公用品与资产管理制度》的固定资产台账定期对账
- 漏洞管理：扫描发现的漏洞按高中低分级，高危 7 天、中危 30 天、低危 90 天内修复
- 无法及时修复的漏洞须有补偿控制措施（如访问限制），并登记备案

## 十二、违规处理

### 12.1 违规情形
- 私自将机密数据拷贝至个人设备或外发
- 共用账号、共享密码、代他人打卡式登录
- 安装破解软件、运行挖矿或翻墙工具
- 私接路由器、关闭安全软件、擅自开放高危端口
- 隐瞒不报安全事件，或私自处置破坏现场
- 第三方违反保密协议、超范围使用数据

### 12.2 处理措施
- 首次一般违规：书面警告 + 强制参加安全复训
- 造成数据泄露或公司损失：追偿损失，通报批评，调岗或降级
- 严重违规（故意泄露、窃取数据、内外勾结）：立即解除劳动合同，保留追究法律责任的权利
- 第三方违规：终止合作、按协议索赔，情节严重者列入供应商黑名单
- 审批人未尽审核义务的，承担相应连带责任

## 十三、办公区域物理安全

### 13.1 出入管理
- 员工凭门禁卡进出，门禁权限正常时间为 7:00-22:00，加班需申请开通 22:00 后权限
- 门禁卡遗失立即联系行政挂失，补办工本费 20 元；挂失前产生的异常开门记录将被核查
- 尾随进入是严重违规：员工有义务阻止陌生人尾随进入办公区，发现可疑人员联系行政前台或保安
- 快递员、外卖员不得进入办公区，前台代收转递

### 13.2 桌面与白板
- 离开工位超过 10 分钟锁屏（与《IT 服务指南》一致），纸质机密文件离桌必收
- 白板上的架构图、客户信息、密码类内容使用后立即擦除，会议室白板由使用人负责
- 打印机、复印机的扫描件与打印残留由使用者当场取走，禁止过夜堆放
- 废弃草稿纸含敏感信息的投入碎纸机，普通废纸投入废纸回收箱

### 13.3 监控与录像
- 办公区、机房、出入口部署视频监控，录像保存 90 天
- 监控调取仅限安全事件调查与公安配合，需 IT 安全组负责人批准并登记
- 禁止员工私自拍摄监控画面、传播监控内容

## 十四、邮件与通信安全

### 14.1 钓鱼邮件识别基线
以下特征出现两个及以上即可判定为高风险，不要点击：
- 发件人地址与显示名不一致，或域名拼写近似官方（如 starccorp.com）
- 要求立即点击链接、输入密码、转账、扫码
- 使用紧迫性用语："账号将被冻结""24 小时内处理"
- 附件为 .exe、.scr、.js、.vbs 等可执行文件，或异常的 .zip、.html 附件
- 收到可疑邮件：不要点击、不要回复，转发至 security@starcorp.com，由安全组分析后统一通报

### 14.2 邮件使用规范
- 重要合同、报价单外发时使用加密邮件或企业网盘分享链接（带有效期与访问密码）
- 禁止使用个人邮箱处理公司业务，邮箱离职即停用，交接期间由部门指定代管人
- 邮件组的成员变更由部门负责人审批，防止离职人员仍接收机密邮件
- 大批量群发（全员通知类）由行政或指定部门统一发送，禁止员工向通讯录全员滥发

### 14.3 即时通讯安全
- 企业微信为公司唯一的即时通讯工作工具，外部群聊涉密内容需脱敏
- 禁止通过个人微信传输公司机密文件
- 收到企业微信中的异常链接、异常文件，先与发件人电话核实（账号被盗的常见路径）
- 安全提醒、钓鱼通报以 IT 安全组官方公告为准，不轻信群内"IT 人员"的私聊指令

## 十五、移动办公与出差安全

- 移动办公必须通过 VPN 接入，禁止在无保护的公共网络直接访问内部系统
- 出差携带笔记本电脑的，保持全盘加密与开机密码开启，托运行李中禁止放置公司设备
- 公共场所开会投屏前，检查屏幕共享内容中是否残留聊天窗口、客户数据
- 手机安装企业微信工作账号的，开启锁屏密码；手机遗失立即在企业微信远程退出工作账号
- 酒店房间内设备无人看管时锁入保险箱或带走；房间送物、维修须确认身份
- 境外出差：提前向 IT 备案设备清单，返回后由 IT 检查设备是否被植入恶意程序，敏感数据出境按监管要求评估

## 十六、附录：员工安全自查清单

新员工转正前、每年安全培训后，对照以下清单自查，各部门负责人抽查：

### 16.1 账号与密码
- [ ] 所有公司系统密码不少于 12 位且包含大小写字母、数字、特殊符号中至少 3 类
- [ ] 未在多个系统使用相同密码
- [ ] 未将密码写在便签、共享文档中
- [ ] 未把企业微信动态令牌截图或转发给他人

### 16.2 终端与数据
- [ ] 电脑全盘加密已开启，屏保 5 分钟自动锁定
- [ ] 防病毒软件（EDR）处于运行状态，未被退出或卸载
- [ ] 个人未使用 U 盘拷贝公司数据
- [ ] 机密级及以上文件存放于企业网盘或业务系统，未存于本地桌面或个人网盘

### 16.3 邮件与通信
- [ ] 未点击来源不明的邮件链接与附件
- [ ] 未在外部 AI 网站粘贴公司代码、客户数据
- [ ] 未通过个人邮箱、个人微信传输工作文件
- [ ] 接到"IT 改密码""领导转账"类电话或消息时，先通过官方渠道核实

### 16.4 办公环境
- [ ] 离开工位会锁屏，纸质敏感文件随手收
- [ ] 白板上的敏感信息使用后已擦除
- [ ] 未尾随陌生人进入办公区，未借用他人门禁卡
- [ ] 发现安全隐患知道上报渠道：IT 安全组分机 8110（7×24）或 security@starcorp.com

## 十七、安全考核与激励

### 17.1 部门考核
- 每季度对各部门进行信息安全考核，指标包括：钓鱼演练点击率、权限复核完成率、培训完成率、事件上报及时率
- 考核结果在管理层例会通报，连续两个季度排名末位的部门，其负责人在年度述职中专项说明
- 发生 P1、P2 级安全事件的部门，取消当季度评优资格（不可抗力与已尽责上报的除外）

### 17.2 个人激励
- 主动报告安全漏洞、拦截钓鱼攻击、避免数据泄露的员工，给予安全积分奖励，可在年度评优中作为加分项
- 安全积分可在行政服务兑换礼品（如公司周边、休假券），每季度兑换一次
- 对隐瞒不报、私自处置安全事件的行为从重处理，与主动上报的从轻处理形成对照，鼓励如实上报

### 17.3 考核数据来源
- 钓鱼演练平台记录、培训系统完成记录、工单系统上报时间、日志审计平台的异常事件统计
- IT 安全组每季度首月 15 日前发布上季度考核结果
- 员工对考核结果有异议的，可向 IT 安全组或 HR 申诉，5 个工作日内答复
