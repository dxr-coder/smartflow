# 星辰科技软件使用与正版化制度

版本：1.0
生效日期：2026-02-01
适用范围：全体员工及使用公司设备的外包人员
归口部门：信息技术部

---

## 一、总则

### 1.1 目的
规范公司软件资产的采购、安装、使用、回收全流程，确保软件使用合法合规，防范盗版软件带来的法律风险与安全风险，提高软件许可（License）利用率，控制 IT 成本。

### 1.2 适用范围
- 公司配发的笔记本电脑、台式机、服务器上安装的一切软件
- SaaS 服务、云服务、在线订阅类工具
- 员工因工作需要申请安装的任何工具软件
- 开发类开源组件、商用库的引入（另见研发规范，本制度约束采购与合规部分）

### 1.3 基本原则
- **合法合规**：所有商业软件必须购买正版许可，禁止使用破解版、激活工具、来路不明的授权码
- **统一管理**：License 由 IT 集中采购、分配、回收，个人不得私自购买软件安装到公司设备
- **按需申请**：标准清单内自助安装，清单外按流程审批
- **安全优先**：任何软件安装前须通过 IT 安全审核，防止恶意软件与供应链风险

## 三、License 管理

### 3.1 许可类型与台账
- **订阅制**（Microsoft 365、Figma、Docker 等）：按月/年订阅，记录席位数、到期日、续费负责人
- **永久许可**（部分 JetBrains、服务器操作系统等）：记录许可数量、授权证明文件、可安装设备数
- IT 建立《软件许可台账》，字段包括：软件名称、版本、许可类型、总数、已用、可用、到期日、责任人
- 台账每季度核对一次，与实际激活数、卸载数比对，差异 5 个工作日内查清

### 3.2 席位分配
- Figma、Tableau 等按席位分配的软件：由 IT 服务台统一开通，用完即回收
- 席位申请：部门负责人审批，闲置席位（连续 30 天未登录）由 IT 提示后回收再分配
- JetBrains 许可证服务器监控在线数，接近上限时 IT 提示管理部评估扩容

### 3.3 续费与到期
- 订阅到期前 60 天，IT 在 OA 发起续费流程，附上年度使用率与成本
- 年使用率低于 30% 的订阅，IT 提出降配或终止建议
- 到期未续费导致服务中断的，由 IT 承担管理责任；紧急续费走财务加急流程（每周三、周五付款日之外的特批通道）

## 四、正版化要求

### 4.1 禁止行为
- 安装破解版、绿色修改版、激活工具生成的授权
- 使用个人购买的许可激活公司设备（许可主体不一致，且离职后存在断供风险）
- 拷贝他人安装包与授权文件在公司内传播
- 在公司设备上安装与工作无关且无授权的付费软件
- 使用盗版字体、盗版素材库用于对外交付物（法律风险由公司承担）

### 4.2 存量清理
- IT 每半年开展一次软件资产扫描，识别未授权软件与超范围安装
- 扫描发现疑似盗版软件：7 天内卸载并出具说明，主动整改的从轻处理
- 整改后复扫仍有存量的，按《信息安全管理制度》违规处理条款处理

### 4.3 员工责任
- 员工是软件使用合规的第一责任人，不得以"同事都有"为由安装未授权软件
- 因盗版软件导致的行政处罚、诉讼、数据损失，由安装人承担相应责任；造成公司损失的，公司保留追偿权利
- 发现他人使用盗版软件的，可通过 IT 服务台或 security@starcorp.com 匿名反馈

## 五、软件申请与安装

### 5.1 安装流程
1. 清单内软件：内网软件商店自助下载安装，或联系 IT 服务台（分机 8100）协助
2. 清单外软件：OA 提交申请 → 直属主管审批 → IT 安全审核 → IT 分发安装包或授权
3. 服务器软件：一律由运维组统一安装部署，禁止研发人员在生产服务器自行安装
4. 安装记录：IT 记录安装日志，纳入软件台账

### 5.2 使用规范
- 标准清单内软件遇到故障：先重启软件/电脑，仍无法解决联系 IT 服务台，提供软件名称、版本号、错误截图、操作步骤
- 需要 IT 远程协助：企业微信 → IT 服务台 → 申请远程协助
- 软件许可仅限工作使用，不得用于对外兼职、售卖服务等非公司业务

### 5.3 卸载与回收
- 员工离职：IT 在离职当日卸载全部许可类软件，释放席位（与 HR 离职流程衔接）
- 岗位调整：不再需要的席位类软件 3 个工作日内回收
- 设备更换/归还：IT 检查并清除许可绑定，重新分配前完成重置
- 员工个人原因需要卸载的，联系 IT 操作，不得自行删除许可组件导致台账失真

## 六、SaaS 与在线服务采购

### 6.1 采购范围
协作工具、AI 服务、设计工具、监控服务、测试服务等一切按订阅计费的在线服务，均纳入 SaaS 采购管理，不得由个人信用卡订阅后转公司报销使用（许可主体与数据风险）。

### 6.2 采购流程
1. 需求部门在 OA 提交"SaaS 采购申请"：产品、用途、席位数、预算、试用结论
2. IT 评估：与现有工具是否重复、安全评估（数据存储地、加密、权限模型、是否有 SOC2/ISO 27001）
3. 财务评估：费用、付款方式、续费机制
4. 法务/合规：合同审核，明确数据归属公司、服务级别、终止条款
5. 审批权限按财务制度执行：5000 元以下部门负责人；5000-20000 元加签财务经理；20000 元以上加签 CFO
6. 采购后由 IT 统一开通账号，禁止使用个人账号承载公司数据

### 6.3 试用管理
- 任何 SaaS 试用期不超过 30 天，试用期数据到期前导出
- 试用转正式：试用期满 15 天内决定是否采购，否则到期自动结束
- 试用期间产生的公司数据（客户对话、文档）不得留在个人账号下

### 6.4 存量 SaaS 治理
- IT 每半年盘点一次 SaaS 清单：名称、部门、席位、年费、活跃率
- 活跃率低于 40% 的 SaaS，续费时要求部门说明，否则降配
- 部门私自开通的 SaaS 被发现后，限期迁入公司主体，逾期停用

## 七、开源软件使用

- 开发引入开源组件须符合公司开源准入清单（License 类型：MIT、Apache-2.0、BSD 等宽松协议优先；GPL/AGPL 商业使用须法务评估）
- 禁止引入无维护、来源不明的 GitHub 项目到生产环境
- 开源组件漏洞纳入漏洞管理流程，高危 7 天内评估升级或缓解
- 对外交付物中包含开源组件的，按 License 要求履行声明、开源义务

---

## 八、服务器与中间件许可

- 生产服务器操作系统、数据库（MySQL、PostgreSQL 开源版优先）、中间件由运维组统一选型与安装
- 商用数据库、商业中间件须持有足够许可数量，禁止超授权部署
- 每年进行一次软件正版化自查，覆盖服务器与终端，自查报告报 CTO
- 云计算资源上使用的商业镜像（Windows Server 等）按云厂商许可规则计费，运维组核对账单

---

## 九、违规处理

- 首次安装清单外未授权软件且未造成损失：下架 + 书面提醒 + 补充安全培训
- 使用破解版软件：通报批评，按情节给予警告直至调岗；造成法律纠纷的解除劳动合同并追偿
- 私自采购 SaaS 导致数据泄露：承担事故责任，参照《信息安全管理制度》第十二章执行
- 审批人明知违规仍批准安装的：承担连带责任
- 供应商在驻场设备安装未授权软件：要求限期整改，情节严重者终止合作

## 十、常见问题

**Q：想装一个清单外的小工具怎么办？**
A：在 OA 提交软件安装申请，写清用途和官网下载地址，直属主管和 IT 安全审核通过后即可安装，一般 1 个工作日内完成审批。

**Q：家里买的 Adobe 许可可以装公司电脑吗？**
A：不可以。许可主体与设备不一致，且公司设备的软件必须由 IT 统一管理。设计岗 Photoshop 为标配，其他岗位如有业务需要可在 OA 申请，需部门负责人和 IT 审批。

**Q：JetBrains 的激活码可以发我一份吗？**
A：不发激活码。公司使用许可证服务器统一授权，安装 IDE 后输入服务器地址即可激活，过期自动续签。联系 IT 服务台（分机 8100）获取服务器地址。

**Q：用个人账号的 ChatGPT/Copilot 处理公司数据可以吗？**
A：不可以。公司数据禁止输入未采购的外部 AI 服务。需要 AI 能力的，由部门申请公司统一采购的企业版，账号由 IT 统一分配，数据条款须明确不用于训练。

**Q：离职前自己装的软件要卸载吗？**
A：公司设备归还前 IT 会统一重置。许可类软件的席位回收由 IT 负责，员工无需自行操作，但应配合确认无个人数据残留。

## 十一、AI 工具与新兴软件管理

### 11.1 使用原则
- 公司已采购的企业版 AI 助手（如 SmartFlow 内部能力、企业版代码助手）为首选
- 未经采购的外部 AI 服务，禁止输入客户数据、源代码、财务数据、未公开业务信息
- AI 生成的代码须经代码审查后方可合入，生成内容的版权风险由引入方评估

### 11.2 新工具引入
- 员工发现效率工具可在 OA 推荐，IT 评估后决定是否纳入标准清单
- 纳入清单的工具须完成：安全评估、License 采购、软件商店上架三步
- 浏览器插件同样纳入管理：清单外插件可能窃取会话凭据，安装须经 IT 审核
